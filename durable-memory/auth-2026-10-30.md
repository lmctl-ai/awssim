# AWS auth integration lessons

Floci 2.3.0 already contains SigV4 helpers, action/ARN mappings, and an IAM policy
engine. Reuse them. Its IAM enforcement intentionally exempts `test`; awssim's
configured identity policies must still apply to that key. The released lmaws
v0.1.27 endpoint override always signs with `test/test`, independently of AWS env
credentials. A separate configured key is tested with independently signed HTTP.

Shared vocabulary: `SIM_AUTH=open|enforce`, `SIM_AUTH_CONFIG=<file>`;
`--auth` and `--auth-config` override environment. Keep cloud errors on the wire;
use the existing CLI envelope for startup/configuration errors. Secrets belong
in a local JSON file, never command arguments, errors, or logs.

The overlay reuses upstream SigV4 canonicalization/crypto, IamActionRegistry,
ResourceArnBuilder and IamPolicyEvaluator. Identify services by the matched
resource and JSON target, never solely by the caller-controlled signing scope.
Use S3 route resolution so an injected JSON target cannot change its IAM action.
JSON query parameters are rejected to prevent query/body resource confusion;
signature scope must agree with the handler account/region/key context.
Unknown routes fail closed in enforcement mode. Health is the sole anonymous
exception. Open mode returns before reading request headers or bodies.

Java SDK v2 signs S3 chunk chains and trailers. Upstream's decoder does not verify
those signatures, so checking only the initial Authorization header is insufficient.
The overlay verifies every signed chunk and trailer before handing the original
wire body to upstream. Tests independently sign accepted and tampered streams.
S3 UNSIGNED-PAYLOAD forms retain AWS's intentionally unsigned-body semantics.

The client returns exit 3 with an ok:false RUN_HOST envelope for HTTP 403. Its
policy errors may be generic AWS_SERVICE_ERROR rather than the wire AccessDenied
code; error detail depends on the SDK operation (signature failures may also be
generic). Assert the stable client
contract and separately assert vendor errors at the HTTP boundary.

Pin both the lmaws binary/checksum and compatible lmscript 0.2.420 compiler:
v0.1.27 reads bytecode v5. The release supplies Linux/macOS x64/ARM64 binaries,
not Windows; Windows CI uses AWS CLI and independently signed HTTP requests.

Scope: single account 000000000000, S3 path-style + DynamoDB/SQS JSON protocols,
header SigV4, 15-minute clock window, 16 MiB encoded bodies. Presigned URLs,
STS/session tokens, SQS Query protocol, IAM administration, conditions, principals,
resource policies, multi-account evaluation, S3 copy/batch/multipart/versioning,
and other services are deferred and
not silently permitted. Config policy fields are validated; unknown fields fail
startup. Missing policy means authentication only; present empty Statement denies.
